### D007 · 2026-09-15 · P0 仅左手点击右半屏

依据：用户要求“先只做左手点击右侧”。固定左手拇指从左向右跨线，预测右半屏触点，缩小首轮实验条件。此决策补充 D002，解决 Q001 中的手别与方向问题；起始姿态、复位和目标分布仍待确定。范围更新于 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)，数据取值维护于 [DATA.md](DATA.md)。结果暂不推广到右手或反向跨线。

### D008 · 2026-09-16 · 统一应用视频显示旋转元数据

依据：首组真实视频编码尺寸为横向 3840×2160，但带有 90° 显示旋转元数据；播放器按元数据竖向显示，OpenCV 默认读取未旋转帧。若各阶段自行处理，会导致标定、轨迹、白闪和渲染使用不同坐标系。

选择：所有视频阶段在解码入口启用 OpenCV 的方向元数据自动旋转，所有图像坐标均定义在旋转后的显示帧上。保留原始视频，不另存覆盖版。限制是该行为依赖视频后端暴露方向元数据；读取后会校验标定尺寸与实际帧尺寸。数据语义更新于 [DATA.md](DATA.md)，模块边界更新于 [ARCHITECTURE.md](ARCHITECTURE.md)。

### D009 · 2026-09-16 · 按设备采集并区分像素与物理尺寸

依据：用户要求使用三台不同样机采集，自动读取像素尺寸，并分别预留物理宽高。浏览器无法可靠识别样机型号、面板原生分辨率或毫米尺寸。

选择：采集前手动选择样机，自动记录浏览器尺寸与 DPR，将设备像素估算与原生分辨率分开。物理尺寸按设备填写，评估根据采集设备选择，避免全局尺寸被误用于其他样机。此决策扩展单设备采集，不改变触点归一化、任务方向或指标。数据语义见 [DATA.md](DATA.md#屏幕尺寸与设备配置)，研究范围见 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)。

### D010 · 2026-09-16 · 使用用户填写的设备屏幕参数

依据：用户已在 `config.yaml` 中填写三台样机的分辨率与毫米尺寸，要求替换采集页面的估算。

选择：新采集格式使用所选设备的配置参数显示和导出尺寸，移除 DPR 估算；保留浏览器 CSS 尺寸用于原有归一化。此决策取代 D009 中新数据使用估算和未知毫米值的部分，旧文件保持原样。HTML 继续独立运行，以内嵌参数快照支持直接打开，配置修订后须同步页面。字段与版本由 [DATA.md](DATA.md#屏幕尺寸与设备配置) 维护。

### D011 · 2026-09-17 · 增加逐次 touch 可视化人工审核（实现方式已被 D012 取代）

依据：用户需要逐次查看 session 中拇指追踪质量，自行决定保留或舍弃，并已确认先实现最小人工审核闭环。

选择：在当前 MediaPipe 0.10.14 基础上采用独立 Python／OpenCV 工具，分离准备缓存与人工审核，优先复用已保存的检测和事件结果。以独立清单表达选择，保存舍弃原因，支持自动保存和续审。这样可在保留数据来源的同时，快速得到可用于轨迹分析的试次集合。

限制与代价：人工选择只能说明该处理版本下的追踪是否可用，不保证指尖准确性或跨线预测成功；审核子集成绩不能直接代表原始 session 的整体性能。工具已实现，人工审核结果尚未产生。接口、字段及评估规则分别由 [ARCHITECTURE.md](ARCHITECTURE.md#逐次-touch-审核工具)、[DATA.md](DATA.md#人工审核数据) 和 [EXPERIMENTS.md](EXPERIMENTS.md#人工审核与子集分析) 维护。

### D012 · 2026-09-17 · session 内单文件选择与浏览器审核

依据：用户明确指出需求只有每次点击保留或不保留，结果与 session 同目录；旧审核目录、多份输出和 OpenCV 窗口不符合需求。

选择：本地浏览器页面提供视频、拇指叠加和保留／舍弃按钮，Python 标准库负责读取与保存。只写 session 内的一个审核 CSV，允许自动保存、修改和续审；不强制原因或备注，不复制视频、坐标、对齐、配置和代码，不生成汇总、manifest 或导出版本。这取代 D011 的缓存目录、原因记录与 OpenCV 界面方案，保留逐次人工选择的目标。数据契约由 [DATA.md](DATA.md#人工审核数据) 维护。

限制：仍依赖已有追踪与核查过的事件，浏览器须支持原始视频编码。人工选择用于指定子集，不自动改写既有实验指标。

### D013 · 2026-09-17 · 任意 session 的通用审核准备

依据：用户要求一个适用于每次新采集的入口，不能依赖此前写死 session 的诊断脚本。

选择：同一审核命令自动发现输入，缺少时运行现有 MediaPipe 和亮度扫描，并核验白闪数量与点击间隔；仅保留一个机器缓存以支持快速重开和失败后的重试。人工结果仍是 session 内的单个 CSV。此决策补充 D012，取代其中“必须已有追踪与事件”及“不生成机器缓存”的限制，不改变模型版本、预测任务和人工选择语义。参数与字段见 DATA，入口见 README。

### D014 · 2026-09-17 · 默认使用完整版手部模型

依据：用户要求修复握持手机时的拇指错位和手指身份混淆；同帧骨架对照表明当前轻量模型存在明显错误，完整版在抽查问题帧上更准确。

选择：保留可运行的 MediaPipe 0.10.14，将默认 `model_complexity` 设为 1。审核默认校验缓存或重新提取，不再自动读取模型来源不明的历史追踪 CSV；显式指定历史坐标仍可用于对照。模型变更后的旧机器结果自动归档，人工结果不静默迁移到新轨迹。这调整 D013 的追踪复用规则，不改变坐标、时间或数据过滤定义。

代价：完整版计算量更大，局部改善不等于整段定位正确；手机遮挡下仍需逐次人工审核。运行入口见 README，缓存约定见 DATA，效果记录见 EXPERIMENTS。

### D015 · 2026-09-17 · 用图像连续性维护拇指身份

依据：用户再次提供第一次点击的连续跳变截图；完整版仍会把下方手指当作拇指，单纯调整模型复杂度、分辨率或逐帧检测不能解决。

选择：采用已有 OpenCV 的 LK 光流维护指尖身份，用反向追踪和图像误差检查结果，拒绝明显偏离实际图像运动的模型候选。模型原始点与处理点都保留，审核可切换对照；丢失如实留空，不用平滑曲线掩盖错误。这补充 D014，明确改变关键点处理而保持模型版本和研究信息边界；具体语义由 DATA 维护。

限制：初始化与重新定位仍依赖模型，光流有漂移和丢失风险；开发会话的人工抽查不能替代真值准确率评估。新增参数须在正式实验前固定，旧审核选择不默默转用于新处理结果。

2026-09-17 用户确认当前版本效果暂时够用。采用本方案作为下一阶段人工审核与轨迹分析的当前实现；先使用现有版本推进数据处理，后续如发现影响分析的具体失败再针对性调整。此确认不改变上述限制或正式实验验收要求。

### D016 · 2026-09-17 · 同时调整手掌与关键点接受门槛

依据：新 `_8` 会话在相同版本、输入尺寸及旧阈值下出现连续漏检。独立顺序重跑复现原始点；内部阶段检查发现手掌拒绝与关键点拒绝均存在，单独降低手掌门槛未解决问题。

选择：默认两道门槛均设为 0.2，保留完整版模型及 D015 的身份连续性检查。0.1 对照虽然有更多输出，却在白闪帧接受了下方手指，不能仅按覆盖率选取。旧缓存自动归档；已有人工选择仍按 DATA 的版本保护规则处理。这改变候选接受门槛，不改变坐标、触点标签、预测时间或保留／舍弃语义。

限制：0.2 减少了新会话的全空点击窗口，仍有漏检和错点风险。开发会话上调参不代表跨设备或正式测试性能；详见 EXPERIMENTS 与诊断报告。

### D017 · 2026-09-17 · 三 baseline demo 与显式真实时间对照 · 已接受

依据：用户要求 B1 跨线投影、B2 统计时间速度外推、B3 真实时间速度外推，并要求预测点不出屏幕。用户确认当前追踪先沿用，`session_20260917075744362_8` 审核已完成。

选择：采用本轮新 baseline 定义；B2 使用剩余时间中位数，具体训练集来源由 D018 明确。B3 是用户明确授权的未来时间例外，单列 oracle 诊断，保留相同的历史速度以观察时间估计的影响。最终预测统一作屏幕边界裁剪，保留约束前结果与标记，便于核对其作用。

本决策调整 D005 在本轮的交付范围：平均触点与 Ridge 暂不实现，B3 编号用于真实时间线性外推；旧实验与方法标识保留原义。原始轨迹、GT、跨线方向及预测时刻不变。算法、分块与指标见 EXPERIMENTS，字段见 DATA，接口见 ARCHITECTURE。

限制：B3 不能支持可部署预测性能结论，也不是保证最优的理论上界；裁剪不能修复错误轨迹。中位数是首轮开发方案，正式泛化实验需独立会话验证。本次仅完成文档规划，代码与配置尚未接入新版方法。

### D018 · 2026-09-17 · 时间中位数直接使用训练集 · 已接受

依据：用户明确“中位数直接用训练集”，当前基本所有 session 都作为训练集，其他会话的审核正在进行。

选择：取消草案中的前 10 次标定／后 20 次比较分块，直接汇总训练集内符合条件的已审核保留试次拟合统一时间先验；当前 session 全部 28 次保留点击进入 demo 候选。允许 demo 试次参与训练统计，结果标注为训练集拟合／诊断。B2 读取统一中位数，B3 逐次读取真实剩余时间，两者仍保持区别。

此决策补充 D017 的统计来源，不改变速度估计和屏幕约束。部分 session 尚未完成审核时，已保留且输入有效的试次可贡献统计；未审核项不默认为保留。新审核结果通过新处理版本纳入，实际使用清单和身份必须可追溯，已有先验与 demo 不覆盖。详细纳入规则和协议见 EXPERIMENTS，文件身份见 DATA。

### D019 · 2026-09-17 · 在 review 内补充四角标注，保留已有审核 · 已接受

依据：用户要求在第一次触摸时一起标注屏幕四角，并明确不愿重新标记数据是否可用。

选择：把一次人工标定接入现有浏览器审核入口，复用同一原始视频和追踪缓存；保留／舍弃结果继续读取原 `review.csv`，四角保存为独立标定文件，供后续投影与 baseline 使用。这样可逐 session 补齐屏幕映射，避免凭相似画面复用别的 session 的四角。此决策补充 D012/D013 的人工标注范围，不改变旧决定、追踪算法或数据过滤。

限制：只保存一帧的静态标定，不能自动处理屏幕运动。存储与身份约定见 DATA，交互与模块见 ARCHITECTURE，运行入口见 README。

### D020 · 2026-09-17 · 保留触摸可单独补标四角，未标注沿用上一触摸 · 已接受

依据：用户要求在同一个 review 程序中逐次标注保留 touch 的手机屏幕四角，没标注的使用上一触摸的四角。

选择：在 D019 的首次标定基础上加入逐 touch 可选标注，复用单个标定 JSON，保留旧单次标定与原审核决定。按时间顺序向后继承，允许重标或恢复继承；页面与三 baseline 共用解析结果。同一动作固定一组四角，避免标定切换制造跨线事件。

限制：这是离线人工几何标定，不能自动追踪动作内的屏幕运动。格式与继承细节见 DATA，信息边界见 EXPERIMENTS。

### D021 · 2026-09-21 · 保留 100 ms 局部速度并统一衰减 · 已接受

依据：100 ms 窗口反映跨线附近的点击局部运动，但直接假设该高速持续到落点会让预测系统性越界；将窗口扩到 1000 ms 虽改善 demo，却可能混入停顿和非点击运动。用户要求恢复局部速度，并尝试乘小于 1 的系数。

选择：恢复 `linear_history_ms=100`，B2/B3 共用 `velocity_scale=0.1`。93 个已标注有效训练试次上，B2 的最小二乘系数约为 0.126；选择 0.1 作为保守、可解释的开发值。保存原始速度、系数和实际应用速度；最终预测仍保留 raw 值和屏幕裁剪标记。

限制：系数来自当前训练／demo 数据，不是独立测试结论；它近似平均减速，无法表达逐次动作的非线性速度变化。正式测试前必须冻结，或在独立验证集上重新选择后冻结。
