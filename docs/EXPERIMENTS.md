## P0 评估协议

### 预测任务与信息边界

主要评估点是指定方向的中线跨越事件。每次预测仅使用该时刻及之前可用的轨迹。实际触摸位置仅在预测生成后用于评估。

当前 demo 的 B3 是用户明确要求的 oracle（使用事后已知时间）例外：只额外使用当前试次从跨线到触摸的真实剩余时间，不使用未来轨迹或真实落点。B3 单独标注、统计，不作为因果预测性能证据，也不保证其误差一定低于 B2。

辅助评估点为触摸前 50、100、150、200 ms：代码以 `prediction_mode=touch_minus_<N>ms` 表示，依据对齐后的触摸时间选择不晚于截止时间的最新视频帧，同时报告实际提前时间。这是事后时间切片分析，不证明系统能在线识别“距离触摸还有多少毫秒”。

跨线试次选择规则和质量规则须在运行前固定，不能使用“触摸前最后一次跨线”这类依赖未来事件的规则伪装成即时触发。

### Baseline

| 方法 | 定义 | 约束 |
| --- | --- | --- |
| B1 跨线投影 | 输出跨线帧上的 thumb-tip `(u,v)` | 仅使用跨线当时的位置 |
| B2 统计时间线性外推 | 跨线位置 + 0.1 × 历史速度 × 训练集剩余时间中位数 | 使用统一、冻结的训练统计量，不按当前点击的真实时间选择时长 |
| B3 真实时间线性外推 | 跨线位置 + 0.1 × 同一历史速度 × 当前试次真实剩余时间 | 显式 oracle 事后对照，允许时间信息泄漏 |

本表是本轮 demo 的新定义，入口为 `scripts/baseline_demo.py`。稳定方法标识为 `b1_crossing_projection`、`b2_linear_stat_time`、`b3_linear_oracle_time`，不复用历史 `b2_linear`。历史实验的 B0 平均触点、固定时长 B2 和曾计划的 B3 Ridge 保留原义；平均触点与 Ridge 不在本轮实现范围。

#### 共用跨线位置与速度

按 DATA 的规则取首次有效左→右跨线采样帧，记时间为 `t_c`、位置为 `p_c=(u_c,v_c)`；三种方法共用该帧。预测点随后冻结到此次点击结束。

四角按 DATA 的逐触摸继承规则解析，同一动作的跨线与速度共用本次固定变换，不连接不同变换下的坐标判断跨线。每次人工标注记录参考帧，实验固定完整四角快照。标定可在离线回看时完成，参考帧可能晚于跨线；本轮方法是在人工提供几何条件下的离线诊断，不代表在线获得屏幕位姿。B1/B2 的拇指运动信息仍只取跨线及之前的帧，不通过后续标注回填前面动作。

B2/B3 使用同一历史速度：在当前动作内、截至 `t_c` 的最近连续有效段中，取过去最多 100 ms 的点，至少 3 个；用时间与 u/v 分别做最小二乘直线拟合，取斜率作为 `velocity_u/v_per_ms`。不跨动作或超过配置最大间隔的轨迹断段拟合，不进行未来插值。位置锚点始终为实测 `p_c`，不使用拟合截距替换。

跨线附近的局部速度通常高于后续整段平均速度，因此 B2/B3 共用 `velocity_scale=0.1` 后再外推。该系数是运动减速的简单近似，不读取当前触摸标签。开发比较使用全部 93 个已标注有效训练试次：B2 最小二乘系数约为 0.126；取更保守且易复现的 0.1。相同系数用于 B2/B3，避免通过各自调参破坏时间方案的可比性。100 ms 窗口和 0.1 系数都属于当前训练 demo 的开发参数；正式测试前必须冻结。

```text
B1_raw = p_c
B2_raw = p_c + velocity_scale * velocity * prior_horizon_ms
B3_raw = p_c + velocity_scale * velocity * (touch_time_video_ms - t_c)
```

B3 的“真实时间”来自对齐后的触摸时间，目前仍受白闪延迟和同步不确定性影响，不能宣称精确物理接触时间。跨线晚于或等于对齐触摸时间、未找到有效跨线时，该试次标记失败；速度不足只使 B2/B3 失败，B1 可保留。

#### 最终预测点的屏幕约束

按用户要求，三种方法均将最终预测限制在完整操作区域：分别对有限的 raw u/v 作 `clip(value, 0, 1)`，使用裁剪后的坐标显示和计算主指标。只限制屏幕边界，不额外把 u 压到右半屏。原始拇指投影不裁剪，跨线和速度仍基于原始轨迹。

保存 raw 与裁剪结果、是否裁剪；每种方法报告裁剪次数和比例，同时提供 raw 误差诊断，以检查改善是否来自边界约束。非有限预测、缺失轨迹或无效时间均失败留空，不能用边界点代替失败。

#### B2 训练集时间先验与当前 demo

当前白盒 baseline 使用 `config.yaml:data_split` 的固定 session 划分。训练统计只汇总 `training_sessions` 中已审核 `keep=1`、完成可信屏幕映射与触摸对齐、具有触摸前有效跨线的试次；测试 session 不参与时间先验。验证集当前为空，不在小规模数据上再拆分。

汇总全部符合条件的训练试次，直接对 `touch_time_video_ms - t_c` 求中位数，作为所有 B2 预测共用的时长；不先求各 session 中位数再平均，也不逐试次替换为真实时间。保存实际贡献试次、样本数、时间分布及源文件身份，生成一次后冻结。无有效训练样本时 B2 明确失败，不回退到当前点击真实时间或旧固定 100 ms。

当前测试 session 为 `session_20260917075240834_5`，全部 30 次审核完成且保留；本次三方法视频展示后 10 次触摸（`trial_0020`–`trial_0029`），保留预测失败。训练统计使用其余 9 个 session，共 231 个符合条件的保留跨线试次，B2 时间先验中位数为 `383.7 ms`。测试 session 不参与该统计；只有 B3 在生成当前预测时直接读取该点击的真实剩余时间。

继续审核其他 session 后，可以通过新处理版本重新拟合训练时间先验，并生成新结果；已有 demo 和先验不自动改变、不覆盖。报告各方法成功数、共同有效试次对照、训练集来源及 oracle 标签；全组覆盖率规则仍见“人工审核与子集分析”。`touch_index` 是试次内编号，完整动作顺序按浏览器时间确定。

上述选择已接入配置：沿用 `prediction.linear_history_ms`、`linear_min_points`，并使用 `velocity_scale=0.1`；当前固定数据划分由 `data_split.training_sessions`、`validation_sessions` 和 `test_sessions` 维护，不能让 baseline 运行时自动扫描全部 session；`time_statistic=median`、`clip_to_screen=true`。新 B2 不使用旧 `linear_horizon_ms`。实际贡献与跳过清单保存在每次运行的时间先验里。

### M2 直接落点实验

#### 问题与方法

M2 固定使用与 M1 相同的首次有效左→右跨线帧 `t_c` 和跨线位置 `p_c`，预测目标为二维增量 `d=touch_uv-p_c`，最终原始预测为 `p_c+d_hat`。三个方法共用同一试次、触发帧、输入截止时间和 `[0,1]` 屏幕裁剪：

| 方法标识 | 定义 | 用途 |
| --- | --- | --- |
| `m2_median_delta` | 所有有效训练 touch 的 `(delta_u,delta_v)` 分量中位数 | 判断不看逐次运动、只用典型偏移能达到的下限 |
| `m2_model_a_ridge` | 因果特征经训练集填充、缺失指示、标准化后，用 Ridge 回归二维增量 | 检查稳定的近线性关系 |
| `m2_model_b_gradient_boosting` | 因果特征经训练集填充和缺失指示后，对 u/v 分别做 Gradient Boosting | 检查小数据下有限非线性是否增益 |

三种方法都不读取当前 touch 的真实剩余时间，因此没有 M1 B3 的 oracle 例外。真实触点只用于构造训练标签或在预测完成后评估。

#### 因果特征

每个特征只能由当前动作开始至 `t_c` 的轨迹计算。首版使用：`crossing_u/v`、动作开始至跨线时长；跨线前 50/100/200/300 ms 的 u/v 最小二乘速度、u/v 位移和有效点数；跨线前 300 ms 的有效比例、最大有效点间隔、路径长度、直线度；50 ms 与 300 ms 速度模长之差。各窗口只保留末端连续有效段，连续性仍用 `tracking.max_gap_ms` 定义。

缺失速度或形状特征保留为空，由每个训练 fold 内的中位数填充并增加缺失指示；禁止先在全训练集填充再做交叉验证。跨线位置必须存在，否则该试次没有预测。每一行保存 `max_feature_time_ms`，验证时断言它不晚于 `prediction_time_ms`。

#### 数据划分与模型选择

固定训练集是 `config.yaml:data_split.training_sessions` 的 9 个 session，固定测试集是 `session_20260917075240834_5`，验证集仍为空。训练集内部使用最多 5 折 `GroupKFold`，分组键为 `session_id`；同一 session 不能跨 fold。候选参数全部来自 `config.yaml:m2`：Ridge `alpha ∈ {0.1,1,10,100}`；Gradient Boosting 比较 `n_estimators ∈ {50,100}`、`learning_rate ∈ {0.03,0.05}`、`max_depth ∈ {1,2}`，固定 Huber loss、`min_samples_leaf=10` 和随机种子 42。

选参目标是各验证 fold 合并后的裁剪后毫米误差中位数，平局时取平均毫米误差较低者。选择完成后，用全部训练 session 重拟合预处理和模型。测试 session 不参与增量中位数、缺失值填充、标准化、候选比较或最终拟合。首轮视频与 M1 保持一致，展示测试 session 后 10 次；量化结果同时保留成功数、覆盖率和失败原因，不能只报告成功样本。

#### 指标、产物与验收

主指标沿用本文件的 mean/median/P90 mm error 和 hit@10/15/20/30 mm，另报告 raw／clipped 误差、裁剪比例、lead time 和以全部协议有效试次为分母的命中率。三种 M2 方法必须在共同有效试次上对比；M1 B1/B2 可作为历史参照，但不混入 M2 模型选择。

一次可追溯运行应输出 `samples.csv`、`feature_schema.json`、`model_selection.json`、冻结模型、`predictions.csv`、`metrics.json`、三个 0.5 倍速视频、配置快照、输入身份、git commit 和未提交补丁。输出目录必须新建，不覆盖 M1 或其他 M2 运行。

验收条件：测试集从全部训练步骤隔离；所有特征时间不晚于跨线；三方法共用跨线帧；预测点显示在屏幕内且保留 raw 值；自动测试通过；真实输出能由量化脚本读取；抽查视频确认跨线时出现预测、点击后才显示 GT；最后把实际样本数、选中参数和指标追加到实验登记。

### M3 小型时序模型

#### 研究问题与公平比较

M3 检验“保留轨迹时间顺序”是否比 M2 的窗口汇总特征提供额外信息。首次左→右跨线帧、预测时刻、二维增量标签、GT、屏幕裁剪、设备毫米尺寸和排除原因全部沿用当前 `single_only` M2 LOSO。比较对象是同一批样本、同一 outer fold 重新拟合的 M2 Model A Ridge 与 Model B Gradient Boosting；增量中位数继续作为下限参考。冻结 tag `m2-baseline` 使用早期跨线规则，不作为该协议的配对预测。

外层评估固定为当前 10 个 session 的 leave-one-session-out。每一轮用 1 个完整 session 测试，其余 9 个 session 训练。M3 必须和对应 M2 fold 使用完全相同的、经过 `single_only` 协议筛选的测试 touch ID；若样本集合不一致，运行失败并报告差异，不允许通过额外过滤改善时序模型成绩。

#### 序列表示

序列字段与插值规则由 [DATA.md](DATA.md#m3-序列样本) 维护。实验固定使用跨线前 300 ms、10 个等间隔时间点。循环层输入只有 `relative_u`、`relative_v` 和 `valid`，以便直接检验时序顺序，不再把 M2 的多窗口速度、路径长度或直线度特征喂给网络。循环层最终隐藏状态与 `crossing_u`、`crossing_v`、动作开始至跨线时长三个静态量拼接，再预测 `delta_u/delta_v`。

#### 固定模型与训练参数

首版不做超参数网格搜索。两种模型除循环单元外保持一致：

| 参数 | LSTM | GRU |
| --- | ---: | ---: |
| 方法标识 | `m3_lstm_tiny` | `m3_gru_tiny` |
| 输入维度 | 3 | 3 |
| hidden size | 16 | 16 |
| recurrent layers | 1 | 1 |
| 方向 | 单向 | 单向 |
| recurrent dropout | 0 | 0 |
| 输出头 | `[hidden; 3 static] -> Linear(19,2)` | `[hidden; 3 static] -> Linear(19,2)` |
| 预计可训练参数 | 约 1.4k | 约 1.1k |

共同训练参数固定为：Smooth L1 loss（`beta=0.05`）、Adam（`lr=1e-3`、`weight_decay=1e-4`）、batch size 32、最多 80 epoch、gradient clip 1.0、随机种子 42。首版不搜索这些值，也不添加隐藏 MLP、归一化层、双向分支或 attention。

每个外层 LOSO fold 内，用训练 session 做 3 折 GroupKFold，仅确定训练轮数：每个 inner fold 最多训练 80 epoch，以验证集裁剪后毫米误差中位数 early stop，patience 10；取三个 best epoch 的中位数并四舍五入，然后在外层全部 9 个训练 session 上从头训练该轮数。inner fold 的标准化只拟合 inner-train；最终模型的标准化只拟合外层全部训练 session。外层测试 session 不参与轮数选择、标准化或训练。

#### 指标、产物与判断规则

指标完全沿用 M2：每个 session 及跨 session 宏平均的 mean／median／P90 mm error、hit@10/15/20/30、裁剪比例、成功数和以全部协议有效 touch 为分母的命中率。另输出相对 Ridge／Gradient Boosting 的逐 session 误差差值和胜负数。首轮只生成统计和模型产物，不生成视频。

一次运行计划输出：`sequence_index.csv`、`sequences.npz`、`sequence_schema.json`、inner-fold 轮数选择、训练曲线、每个外层 fold 的 LSTM／GRU 权重和预处理状态、`predictions.csv`、`per_session_metrics.csv`、`metrics.json`、配置快照、输入身份、git commit 和代码补丁。M2 对照预测及其 tag／commit 写入 manifest，但不复制修改 M2 模型。

首轮结果按以下预先约定解释：相对 Gradient Boosting，若宏平均 median error 改善至少 1 mm 或 hit@10 提高至少 5 个百分点，并且至少 6/10 个测试 session 不劣化，才进入多随机种子复核；差异落在上述范围内视为暂不明确；明显更差则不扩大模型。单种子首轮只能筛选方向，不能作为时序模型稳定优于 M2 的最终结论。

#### 实现与验收结果

1. 先实现并测试序列构造；断言所有来源时间 `<= t_c`、跨缺失段不插值、样本 ID 与 M2 完全一致。
2. 实现共享的小型循环回归器，再分别实例化 LSTM／GRU；记录实际参数量并要求小于 5k。
3. 在一个 outer fold 上做 smoke test，核查 train／inner-val／test session 完全隔离和输出可复现。
4. 跑完整 10-fold LOSO，无视频；生成与冻结 M2 的配对汇总。
5. 结果满足上面的进入条件后，才增加 3 个固定随机种子复核；首版不扩大网络。

实现入口为 `scripts/m3_sequence_models.py`，新增依赖为 `torch>=2.2,<3`，配置位于 `config.yaml:m3`。smoke test 和完整 10-fold LOSO 均通过；结果位于 `outputs/m3_sequence_models_v2/`。每个 fold 使用 192–212 个训练序列和 6–29 个测试序列，所有 218 个协议有效测试序列均成功输出。

结果：

| 方法 | mean mm | median mm | hit@10 | hit@15 | hit@20 |
| --- | ---: | ---: | ---: | ---: | ---: |
| M2 Model B Gradient Boosting | 10.87 | 9.28 | 54.0% | 80.8% | 91.2% |
| M3 LSTM tiny | 11.85 | 11.01 | 45.4% | 67.1% | 87.9% |
| M3 GRU tiny | 11.84 | 10.23 | 50.8% | 70.9% | 86.6% |

结论：LSTM 只有 1/10 个 session 的 median error 不高于 Gradient Boosting，GRU 为 4/10；两者均未达到预设的“median 改善至少 1 mm 或 hit@10 提高至少 5 个百分点，且至少 6/10 session 不劣化”的进入条件。因此首轮不增加随机种子、不扩大网络，也不生成视频。这个结果只说明当前小数据、当前序列表示和追踪质量下，时序模型没有超过 M2 Model B，不能证明所有时序模型都无效。

### 指标

设预测与真实触点差为 `du,dv`，操作区域物理宽高为 `W_mm,H_mm`：

```text
error_mm = sqrt((du * W_mm)^2 + (dv * H_mm)^2)
lead_time_ms = touch_time_video_ms - prediction_time_ms
hit@r = 有效预测中 error_mm <= r 的数量 / 有效预测数量
```

报告 mean、median、P90 error，hit@10mm、hit@15mm、hit@20mm、hit@30mm，以及 lead time 分布。P90 使用线性插值分位数，具体实现与版本写入运行记录。

同时报告全部采集试次数、协议有效试次数、成功预测数、失败和排除原因；覆盖率为成功预测数 / 协议有效试次数。另报告以协议有效试次数为分母的命中率，将未能预测计为未命中，防止仅保留容易样本。每项统计写明分母；对比方法时同时给出共同有效试次上的结果。

缺少物理尺寸时只报告归一化欧氏距离，明确单位为 normalized，并将毫米指标标记不可用。没有有效样本时结果记为不可用，不记为零误差。

对齐不确定性与 lead time 一并报告；提前时间不大于时间不确定性的样本不能作为可靠提前预测的证据。白闪近似对齐得到的结果必须注明限制。

### 输出与人工核查

* 逐试次预测、实际触点、误差、提前时间与有效性明细。
* `error vs time-before-touch`、`hit@20mm vs time-before-touch` 和预测/真实触点散点图；缺少毫米标定时不生成伪毫米曲线。
* 叠加视频显示屏幕边界、中线、拇指尖、历史轨迹、跨线时刻、预测和实际触点、误差与提前时间。实际触点标明为事后 GT。
* 核查四角映射、触摸/白闪配对、跨线触发帧，以及轨迹特征的最大时间戳不晚于预测帧。
* 核查所有过滤计数与原始试次数一致，时间先验只汇总已登记且符合条件的训练试次；当前 demo 明示训练集结果。B2 共用冻结先验，B3 逐次使用真实时间的例外显式登记。

## 人工审核与子集分析

人工审核用于确定指定追踪结果中的可用试次，机制由 D012 接受，工具入口为 `scripts/review_session.py`。数据字段见 [DATA.md](DATA.md#人工审核数据)，不在此重复维护。

### 审核依据与信息边界

* 在审核前固定要检查的追踪来源及规则，以是否追踪到操作拇指、点位是否明显错误、相关动作片段是否可查看、事件配对是否可靠等质量问题作决定。
* 审核界面不提供落点预测误差或预测命中结果，不根据模型预测好坏选择保留试次。
* 整个动作和点击后的帧可用于事后核查，但审核不能补写指尖坐标、未来插值或修改 prediction time。随后 B1/B2 遵守因果信息边界，B3 仅使用上述已登记的真实剩余时间例外。
* 白闪预览区间仅用于定位和检查，不代表跨线窗口；区间检出比例也不是经人工标注的指尖准确率，不用一个全片段比例自动决定保留。

### 清单用于分析时的规则

审核选择不直接改变既有评估。后续实验读取 session 内已完成审核的清单，保存实际使用的清单路径、哈希及选中的 touch 标识；未审核项不默认为保留。

区分两种用途：

1. **可用轨迹子集分析**：只使用保留试次研究轨迹与落点关系。报告原始数量、保留／舍弃数量及子集内成功预测数，明确结论条件为人工筛选后的试次。
2. **原始 session 的整体评估**：协议有效但模型漏检、追错手或定位失败的试次，继续计入覆盖率和整体命中率的分母。因采集、配对或操作问题提出的排除，需要按正式实验事先固定的规则判断，不能只凭 `keep=0` 自动扣除。

两种用途均记录实际过滤规则、时间不确定性和训练／验证／测试划分；审核不改变按 session 或连续试次块划分的约定。正式排除规则和数值阈值仍由 Q007 待定，不将人工审核结果自动升级为正式研究结论。

使用 `scripts/m2_all_sessions.py` 对 `config.yaml:data_split` 中的 10 个 session 逐一测试。每轮将当前 session 作为测试集，其余 9 个 session 作为训练集；每轮重新拟合增量中位数、Ridge 和 Gradient Boosting。运行使用 `--no-render`，只保存模型、预测、指标和汇总 CSV，不生成视频。旧冻结结果的每个 session 使用全部保留 touch；未检测到有效跨线的试次保留在分母中并记录失败原因。

输出位于 `outputs/m2_leave_one_session_out_v2/`，总表为 `summary.csv`。跨 session 的宏平均结果如下，百分比是各 session 指标的简单平均，不是按 touch 数加权：

| M2 median delta | 15.00 | 12.83 | 34.9% | 58.6% | 74.1% |

### 多次跨线过滤协议 · 2026-09-22 · 完成

问题：采集页面只记录成功触摸，没有记录触摸前的失败尝试。若同一动作在真实 touch 前多次从左侧进入右侧，单纯取第一次跨线会把失败尝试和最终 touch 错配。

处理：`visual_pretouch.find_crossings()` 统计每个动作在 touch 截止前的全部有效左→右跨线。当前 `config.yaml` 设置 `prediction.crossing_policy: single_only`；M2 样本仅纳入恰好一次跨线的保留有效 touch，多次跨线行保留在 `samples.csv` 并记录 `multiple_left_to_right_crossings_before_touch`。该过滤同样是 M3 的共同样本协议，不改原始视频、touch CSV、review、追踪缓存或四角标定。

实际统计：300 个 touch 中 261 个保留，43 个保留 touch 被排除，剩余 218 个单次跨线样本。10 个 session 的保留／多次／可用数量依次为 `25/9/16`、`10/4/6`、`27/5/22`、`25/3/22`、`30/1/29`、`28/5/23`、`30/6/24`、`28/2/26`、`30/4/26`、`28/4/24`。这里的“可用”还要求 GT 有效。
