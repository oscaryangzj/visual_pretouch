# 第 9 次点击：MediaPipe 骨架误识别核查

0.10.14 的四组独立实例均从第 0 帧顺序处理到 1440 帧，阈值 0.5、最多一只手。参数见 config.yaml，完整 21 点结果保存在 results.json。未改模型版本、原缓存、人工审核选择或共享模型配置。

## 确认结果

- 读取 landmark[4]，不是 landmark[20]；BGR→RGB、缩放还原及原视频时间戳检查正常。
- 原配置 lite480 重跑，在记录区间与已有缓存双方都有点的帧上最大坐标差为 0 像素。把坐标直接画在对应解码帧上仍出现错误，因此不是浏览器导致的这些误识别。
- 1395 帧（23.27325 秒）中，轻量版整套手骨架错误，拇指点落在真实指尖下方；full480 的拇指点位于真实指尖附近。
- 1400 帧中，lite480 无输出；full480 拇指点仍接近真实尖端；static480 与 lite1080 将 4 号点放到手机底部、把其他手指骨架放到真实拇指上，表现为手指身份混淆。
- 抽查 1380、1390、1395、1396、1400、1405、1410 帧：full480 没有出现上述明显的拇指／下方手指交换。其他被手机遮挡关节仍是模型推测，不代表整手骨架准确。

## 边界

这是一个点击片段的视觉对照，没有逐帧人工坐标真值，未计算定位准确率。不能据此声称整个 session 已修复。完整版曾在另一组裁剪视频上覆盖率更低，不能推广成所有输入都更差。下一步应在完整 session 上单独复核 full480，先不覆盖原缓存和已有审核决定。
